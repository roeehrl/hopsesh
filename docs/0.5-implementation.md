## Implemented

- One shared passive observer for desktop and CLI headless hosts, with OS-held
  namespace ownership, canonical config/state identity, immutable epoch/sequence
  snapshots and private same-user Unix sockets or Windows named pipes.
- Filesystem change coalescing and fallback reconciliation; source freshness,
  completeness and inventory absence remain separate. Source-owned bounded Git
  metadata keeps repository grouping accurate. Module observation cannot execute
  vendor commands, adopt imports, write transcripts or register accounts.
- GUI subscriptions replace the desktop five-second collector and local frontend
  session/presence polling. Machine progress uses backend notifications instead of
  a one-second browser poll. One shared remote scheduler scans newly approved
  machines, combines simultaneous client requests, uses one deadline timer and
  serializes remote collections. Healthy direct machines refresh every five
  minutes; relay sources refresh before their original evidence expires. Network
  failures back off to one hour. Authentication/host-key failures need explicit
  retry; background scans never prompt or accept keys. Sleep cancels collection;
  resume requests fresh evidence. CLI TUI starts or attaches the shared observer.
  Per-owner diagnostics expose notification/coalescing/collection/failure counts,
  collection duration and subscriber counts without adding timers. The native
  CLI idle qualification checks zero, one and five clients; it measures collection
  counts, not OS energy usage or the release's memory/CPU budget.
  Passive Git probes disable optional index locks and repository filesystem-monitor
  callbacks; a regression test verifies unchanged index bytes and no monitor
  execution. This also fixes the disposable browser-home reset/index-lock race.
- Shared schema 5, strict typed settings, OS lock and compare-and-swap revision.
  Each successful save advances the caller's revision; stale writers are refused.
  CLI changes are adopted by GUI observation. Runtime fallback interval changes
  take effect without treating cached evidence as a new observation.
- CLI runtime start/serve/status/stop and reviewable per-user login registration
  plans for launchctl, systemd and Task Scheduler. A drain gate refuses stop during
  active transfers. Background task shutdown precedes release of ownership.
- Metadata-only desktop detection; missing-app installation uses signed manifests
  and local macOS signing/notarization verification. Existing installs are refused
  by the new installer. Windows extraction limits and duplicate files are checked.
  Existing Windows installs publish through a write-ahead manifest; partial
  publication and interrupted updates restore the complete previous file set.
- The pending real source lineage acknowledgment was recovered through the normal
  retry path after a narrow empty-branch origin completion fix. Both native
  conversation SHA256 hashes stayed unchanged; both durable receipts are applied.
- Explicit relay key initialization, fingerprint approval, scoped grants,
  credential input through stdin, local revocation, redacted enrollment status
  and runtime-owned adaptive HTTPS delivery.
- Offline recipient encryption uses pinned `filippo.io/age v1.3.2`; domain-bound
  Ed25519 signatures authenticate routing, namespace, operation, expiry and
  ciphertext against independently approved keys. This is packet encryption,
  not a claim of a qualified Noise channel or forward-secret persistent channel.
- Relay operation intent is written before actions; replay recovers the encrypted
  result, changed input under an existing operation ID is refused, and interrupted
  native outcomes are treated as uncertain. Delivery acknowledgment follows durable
  processing and reply publication. Reply routing is separate from native actions.
- Receiving reuses existing movement planning/apply and adds source endpoint
  binding, approved repository roots and symlink containment checks. It cannot
  launch/stop agent programs or grant cloud sessions general machine access.
  Prepared plans, private conversion items, accepted native IDs and source
  acknowledgments are durable. A receiver restart restores the accepted operation;
  undo verifies the authenticated peer's durable receipt and journal binding.
  Sending permissions are separate from incoming machine access. CLI push uses
  the existing peer protocol over private runtime IPC and encrypted relay delivery.
  Pull now freezes source-owned exports, restores the accepted native installation,
  acknowledges typed lineage receipts, and links both endpoints' undo journals.
  Pending source acknowledgments survive restart, appear in Activity and use its
  existing receipt retry. Undo waits for confirmation. The complete transport UI
  and remaining failure qualifications are still in progress. GUI Internet
  delivery settings initialize public identity explicitly, enroll using masked
  credential input, show health/lease expiry and independently approve sending,
  bringing, local receiving and local sharing. CLI pairing uses the same scope
  validation; selecting roots alone grants no transcript or transfer access.
  Device previews require sharing/export approval and exact source-owned keys,
  enforce repository containment and return at most 20 messages. Observation-only
  connections are excluded from receiving destinations. Revocation disables the
  corresponding machine immediately; approval metadata excludes private keys and
  routing credentials.
- Device enrollment uses a signed native-key possession proof and verified
  account authorization. Headless CLI login follows RFC 8628 code expiry,
  denial and increasing polling delays. Desktop approval uses the external
  browser, S256 PKCE and an ephemeral literal loopback callback; cancellation
  closes the listener and exposes no OAuth secrets through the GUI bridge.
  Access JWT signature, issuer, audience, expiry and app type are verified before
  paid authorization-object allocation. User routing spaces derive from issuer
  and subject, never email or client-supplied namespace. The single authorization
  object bounds pending requests; gateway rate limits precede allocation.
  Browser review requires matching origin, a custom header and an account-bound
  review nonce. Lost token responses replay one bounded credential without a
  second enrollment. Fresh cloud keys cannot enroll as personal devices.
  Account-provider/Access provisioning and hosted login are still unqualified;
  [operator setup](relay-enrollment.md) describes required configuration.
- Separate experimental Worker/SQLite-backed Durable Object/private R2 definition.
  The exact handler has tests for auth, quotas, expiry, cursor acknowledgment,
  ordering and duplicate IDs. Credentials use pinned `jose 6.2.12` JWT verification
  before allocation of a paid authorization-space object. Worker builds with
  Wrangler 4.148.0. A Go/Node round trip exercises the actual Worker handler.

- Typed nested settings preserve sibling fields. Setting aside an incompatible
  config uses the same writer lock and a distinct backup name.
- The sender freezes the original request and reuses its completed source journal
  across owner restarts. Changed source/target/options under one operation ID are
  refused. An interrupted source replay is explicitly uncertain; an undone
  operation requires a new ID.
- Rejected signatures, revoked deliveries and unsolicited replies are durably
  quarantined as bounded metadata/digests and acknowledged without blocking later
  valid transfers. Sensitive reads check the opened owned object, refuse links and
  bound allocation before reading contents.
- Relay enrollment and credential renewal are adopted by the running owner.
  Disabling/replacing the connection cancels in-flight calls and joins the previous
  listener before starting another. Exact settings/credential watches ignore
  sibling delivery blobs; logs, downloads, staging and queues no longer wake the
  passive collector. Watcher failures are surfaced with fallback reconciliation.
- The TUI subscribes to an available shared runtime, preserves selection and
  remote results, and postpones updates while a plan is under review. Incomplete,
  expired or disconnected observations leave cached rows unknown.
- Provider-specific immutable verified bootstrap plans distinguish installation,
  startup support, pending authorization and connection. Scripts verify the
  release signature and exact archive SHA256 before installation. Redirects,
  failed signatures and altered archives cannot install a binary.
- Actual session startup creates fresh scoped keys and a bounded lease. Resume
  supersedes the previous incarnation; forks have independent slots. Connectors
  expose only the bound session's observation and opt-in native transcript export.
  They cannot list a device, receive/undo transfers, run shells or change settings.
  Current Codex Cloud native transcript visibility remains unsupported pending
  qualification. Claude hooks check `CLAUDE_CODE_REMOTE=true`.
- Cloud exports seal an immutable complete-record JSONL prefix with its digest,
  read/export byte counts, record count and explicit omitted-tail count. An
  unfinished final vendor write is excluded and disclosed; a malformed completed
  record fails rather than silently changing history. Subsequent writes cannot
  mutate the returned checkpoint. Native read-only encrypted delivery exercises
  the partial-tail case through the actual connector CLI and relay handler.
- Dedicated download Worker and local signed-release publisher. Publication is
  separately authorized, checksum-bound and conditional in R2; existing release
  objects cannot be overwritten. All selected archives are verified before the
  first upload. The cloud CDN distributes CLI archives only.
- Mailbox deletion commits logical removal plus cleanup intent before R2 deletion.
  Partial R2 cleanup cannot strand a visible missing object. Expired dedupe receipts
  and devices release quotas; alarms wake at actual expiry times during idle leases.
- Encrypted chunk delivery supports requests/results up to 24 MiB of serialized
  JSON, with per-peer object binding, part/final hash validation, immutable upload
  intent, and bounded private local staging. This is a serialized limit; base64
  native attachments reduce usable raw size. Small/chunked forms share one native
  operation tombstone. Reply renewal uses a signed outcome encrypted to the local
  owner for up to 24 hours, without another native action. Expired large-object
  recovery remains fail-closed pending further retention qualification.
- Runtime logs rotate only on writes, bounded to four MiB including three archives.
  OS supervisors do not retain an unbounded log descriptor. Actual supervisor
  registration, activity and definition status are separate. Manual headless
  ownership drains before login-service handover; repeated enable preserves the
  running owner and repeated disable is idempotent.
- CLI `runtime doctor` and Settings' diagnostic download expose allowlisted health
  metadata without paths, titles, conversations, credentials or log contents.
- GUI observation cannot replace a newer explicit scan or overwrite settings
  saved during adoption. Click-stability tests exercise backend observation events.

## Verification so far

A-B-C-A and A-B-C-B-C-A-B with Claude, Codex and alternating agents, destination
owner restart/retry, and independently travelling originals/sibling forks.

pull cannot miss newly installed sessions; background observation keeps its
cached source timestamps. Unverified account returns remain portable replicas,
preserving existing native sessions. These disposable machine homes exercise
each job's native OS; mixed-OS machines remain a distinct gate.

Relay delivery now uses one authenticated notification stream per owner, with
five-minute reconciliation and bounded HTTP fallback. Actual local SQLite/R2
tests pass notification upgrade, committed-message hints, socket quota, routing
renewal and revocation; native race tests verify idle suppression, immediate wake
and joined shutdown. See [relay notifications](relay-notifications.md). Hosted
hibernation and OS energy measurements remain separate gates.

checks pass. Native macOS detached owner, duplicate owner reuse, stop, actual
launchctl registration/start/disable pass in disposable config/state namespaces;
the temporary OS registration was removed. Linux/Windows CLI cross-builds pass;
native behavior on those platforms remains a CI qualification. An actual
CLI/private-IPC/age/verified-HTTPS/Worker/native-writer test passes, including
receiver restart between planning and applying, preserved Codex native ID,
