## Durable incoming notification recovery

Recipient recovery is now implemented in addition to active caller reconciliation.
Publication commits coalesced notification demand with the message, and the
existing shared alarm retries only pending delivery hints with bounded backoff.
ACK, expiry and revocation retire demand; offline sockets stop retries and
authenticated reconnection rearms a nonempty mailbox. Retrying a hint never
replays a native operation or exposes payload content. Sequence/schedule checks
preserve concurrent publications and acknowledgments. Subscription authority and
capacity are rechecked after the new storage await.

The actual SQLite/R2 regression fails on the old Worker after discarding the
first hint without polling its mailbox. The corrected platform passes, including
offline reconnection, simultaneous connection-quota requests, renewal and
revocation (4.55s scenario / 6.126s package). All 54 infrastructure checks pass,
including lost hints across recreated Mailbox instances, exponential backoff,
partial ACK, concurrent publication and stopping for offline/revoked/expired
recipients. Native three-OS lineage and revised hosted load/cost qualification
remain required. The implementation follows the research refinement in
`runtime-cloud-relay-design.md`; no hosted deployment is claimed.

## Active-request recovery after a missed notification

A connected WebSocket does not guarantee that every mailbox hint arrives. The
Worker deliberately keeps an accepted message successful if its best-effort hint
fails. Previously an active caller with a connected socket could leave a committed
reply behind the five-minute idle reconciliation interval. A regression with real
WebSocket transport, encryption, authorization and durable reply dispatch fails
against the old listener: the caller reaches its three-second deadline despite
the committed reply. The reply becomes visible after the initial activity poll,
so an immediate wake alone cannot satisfy this regression.

An outstanding caller now reconciles at most one second after a successful empty
poll even while notifications are connected. Completion, cancellation or lease
expiry removes that demand; stale activity does not wake an idle connected
listener. Error backoff and Retry-After remain in force. The regression also
verifies that completed calls do not retain fast idle polling. The full native
macOS relay race suite passes (92.210s), lint reports zero issues and Windows test
compilation succeeds. Three-OS native qualification and Windows fork diagnostics
are dispatched using byte-identical relay files at diagnostic revision `df9bedc`.
This proven reply-recovery defect is not yet the established cause of the
intermittent Windows fork stall. A missing incoming-request hint at an idle peer
remains a separate recovery case; caller-side polling alone cannot wake that peer.
Evidence: `qualification/active-hint-recovery/verified.json`.

## Implemented

- One shared passive observer for desktop and CLI headless hosts, with OS-held
  namespace ownership, canonical config/state identity, immutable epoch/sequence
  snapshots and private same-user Unix sockets or Windows named pipes.
- Filesystem change coalescing and fallback reconciliation; source freshness,
  completeness and inventory absence remain separate. Source-owned bounded Git
  metadata keeps repository grouping accurate. Module observation cannot execute
  vendor commands, adopt imports, write transcripts or register accounts.
- GUI subscriptions replace the desktop five-second collector and local frontend
  session/presence polling. Machine progress uses backend notifications instead of
  a one-second browser poll. One shared remote scheduler scans newly approved
  machines, combines simultaneous client requests, uses one deadline timer and
  serializes remote collections. Healthy direct machines refresh every five
  minutes; relay sources refresh before their original evidence expires. Network
  failures back off to one hour. Authentication/host-key failures need explicit
  retry; background scans never prompt or accept keys. Sleep cancels collection;
  resume requests fresh evidence. CLI TUI starts or attaches the shared observer.
  Per-owner diagnostics expose notification/coalescing/collection/failure counts,
  collection duration and subscriber counts without adding timers. The native
  CLI idle qualification checks zero, one and five clients; it measures collection

  Passive Git probes disable optional index locks and repository filesystem-monitor
  callbacks; a regression test verifies unchanged index bytes and no monitor
  execution. This also fixes the disposable browser-home reset/index-lock race.
- Shared schema 5, strict typed settings, OS lock and compare-and-swap revision.
  Each successful save advances the caller's revision; stale writers are refused.
  CLI changes are adopted by GUI observation. Runtime fallback interval changes
  take effect without treating cached evidence as a new observation.
- CLI runtime start/serve/status/stop and reviewable per-user login registration
  plans for launchctl, systemd and Task Scheduler. A drain gate refuses stop during
  active transfers. Background task shutdown precedes release of ownership.
